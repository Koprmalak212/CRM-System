CRM-SYSTEM: BUILD PLAN IN STAGES
================================
Goal: add the 12 suggested features. Each stage is built, tested and committed on its own, so
the site keeps working after every stage and nothing is half finished.

Rules that apply to every stage
  - Same look as now (dark navy, lime, butter yellow), same spring motion, nothing hard-coded
    that breaks reduced motion.
  - Security as before: CSRF on every form, prepared statements, output escaped, rate limits,
    admin-only where personal data or secrets are involved, every sensitive action in the log.
  - New tables go in database/schema.sql AND are applied to the live database. Demo data and
    "Remove demo data" are extended for every new table (rows tagged is_demo).
  - Every stage ends with: tests/run.php (new checks added), the crawl + click-through +
    accessibility scan at 360 / 768 / 1440 px, an entry in Settings > Tests (baseline version
    bump), and a local git commit. Nothing is pushed to GitHub without asking you.
  - setup.php --reset keeps the user's own data, as it does now.


STAGE 1  Companies as their own section                                        (suggestion 1)
-----------------------------------------------------------------------------------------------
Needs
  Database   new table companies (name, address, postcode, city, country, KvK number, VAT
             number, email, phone, website, notes, is_demo).
             users.company text becomes users.company_id; existing company names are migrated
             into companies. invoices get an optional company_id.
  Pages      companies.php (list: search, sort, pagination), company.php (details, its users,
             invoices, open tickets later), company_edit.php (add / edit / delete with a
             confirm). Users page and user page read the company from the new table and link
             to it. invoice_new.php gets a company picker that fills in the customer fields.
  Navigation "Companies" item in the sidebar.
  Demo data  the 14 demo companies become real company rows with addresses and KvK numbers.
  Tests      company CRUD, a company with users can not be deleted by accident, link from
             users and invoices, migration of old data.

STAGE 2  Notes and activity timeline                                           (suggestion 3)
-----------------------------------------------------------------------------------------------
Needs
  Database   notes (about = user or company, kind = note / call / email / meeting, text,
             author, created_at, is_demo).
  Pages      "Add note" form and a timeline on user.php and company.php. A company timeline
             also shows invoices issued and (after Stage 3) tickets opened.
  Rules      notes are text only (escaped), length capped, author is the signed-in account.
  Demo data  a few notes per demo company and user.
  Tests      add / list / escape, can not write a note on a missing user or company.

STAGE 3  Tickets / support requests                                            (suggestion 2)
-----------------------------------------------------------------------------------------------
Needs
  Database   tickets (reference TCK-0001, company, user, subject, description, status open /
             in progress / waiting / resolved / closed, priority low / normal / high / urgent,
             assignee, timestamps) and ticket_comments (author, text, created_at). is_demo.
  Pages      tickets.php (filters by status, priority, assignee, company; sorting; pagination),
             ticket.php (details, comment thread, change status / priority / assignee),
             ticket_new.php. "Tickets" in the sidebar. Open tickets show on the company and
             user pages and count on the Overview.
  Demo data  about 40 tickets with comments across the demo companies.
  Tests      create, comment, status flow, filters, validation, XSS-safe output.

STAGE 4  Global search                                                         (suggestion 4)
-----------------------------------------------------------------------------------------------
Needs
  Pages      search.php: one box searches users, companies, invoices and tickets, results are
             grouped with counts and link to each item. The top-bar search sends people there.
  Notes      the two hidden easter eggs in the search box must keep working exactly as now.
             Searches use prepared statements and are rate-limited; wildcard characters typed
             by the user are escaped.
  Tests      each result type is found, no results state, LIKE characters are escaped,
             easter eggs still trigger.
  Depends on Stages 1 and 3 (so companies and tickets exist to be searched).

STAGE 5  Export and import (CSV)                                               (suggestion 5)
-----------------------------------------------------------------------------------------------
Needs
  Export     export.php?type=users|companies|invoices|tickets, admin only, UTF-8 with BOM so
             Excel opens it, cells starting with = + - @ are neutralised (CSV injection),
             every export is written to the activity log, rate-limited like report downloads.
  Import     import.php for users and companies: upload a CSV, rows are validated, good rows
             are added, bad rows are listed with the reason, duplicates (same email / KvK)
             are skipped. Admin only.
  Limits     Apache currently refuses uploads over 256 KB (LimitRequestBody); the import page
             stays inside that limit and says so. The file is read, never stored or executed.
  Tests      round trip export then import, injection cells, malformed files, oversized
             files, non-admin gets 403.

STAGE 6  Notifications                                                         (suggestion 6)
-----------------------------------------------------------------------------------------------
Needs
  Database   notifications (kind, title, text, link, created_at, read_at, unique key so the
             same event is never announced twice).
  Logic      a refresh that runs when pages load (at most every few minutes) and creates
             notifications for: invoice became overdue, backup failed, a monitored service
             is down (Uptime Kuma / endpoint checks), urgent ticket opened.
  Pages      a bell with an unread count in the top bar and a small dropdown, plus
             notifications.php (all, mark read, mark all read).
  Email      optional: if an address is set in Settings, the same events are also sent by
             email through the mailer built in Stage 8 (so this part is finished there).
  Tests      each event type, no duplicates, mark as read, reduced-motion safe bell.

STAGE 7  Two-factor sign-in for staff accounts                                 (suggestion 7)
-----------------------------------------------------------------------------------------------
Needs
  Database   admins get totp_secret (stored encrypted with the existing key), totp_enabled,
             recovery codes (stored hashed).
  Code       authenticator-app codes (RFC 6238, 6 digits, 30 seconds), written without
             outside libraries and tested against the official RFC test values.
  Pages      Settings > Account: turn on (secret key and otpauth link to type or paste into
             an app, confirm with a first code, then 10 one-time recovery codes are shown
             once), turn off (needs password + code). New login_2fa.php step after the
             password. A QR code is not included because it needs a library; the manual
             key works in every authenticator app.
  Security   the step is rate-limited and locks out like the password step, a code can not
             be used twice, an admin can reset another person's 2FA from Settings > Team
             (logged).
  Tests      RFC vectors, wrong / reused / expired codes, recovery code single use, lockout,
             login still works for accounts without 2FA (the default admin / admin stays).

STAGE 8  Email, password reset and invitations                                 (suggestion 8)
-----------------------------------------------------------------------------------------------
Needs
  Mailer     includes/mailer.php: sends with PHP mail() (or SMTP settings if you enter them)
             and records every message in a mail outbox table. XAMPP has no mail server by
             default, so on localhost the outbox page (admins only) is where you read the
             message and copy the link. Real delivery needs an SMTP account from you.
  Reset      "Forgot password?" on the login page, forgot.php, reset.php. Tokens are random,
             stored hashed, valid for 1 hour, single use, rate-limited, and the page never
             reveals whether an account exists. After a reset all other sessions end.
  Invites    Settings > Team: invite by email with a role and integration permission, the
             person opens a link, picks a password and (optionally) turns on 2FA.
  Notices    finishes the email part of Stage 6.
  Tests      token expiry, reuse, tampering, unknown account looks identical, invite flow.

STAGE 9  Trends on the Overview                                               (suggestion 9)
-----------------------------------------------------------------------------------------------
Needs
  Charts     revenue per month (payments, last 12 months), new users per month, ticket volume
             per week and average open time; drawn like the existing activity chart (no
             chart library), with hover values, accessible labels / data table fallback.
  Data       queries only; demo data is extended with 12 months of history so the charts
             have something to show.
  Tests      numbers match the database, empty state when there is no data.
  Depends on Stage 3 for ticket charts.

STAGE 10  Recurring invoices and PDF invoices                                (suggestion 10)
-----------------------------------------------------------------------------------------------
Needs
  PDF        invoice_pdf.php?id=: a PDF made by our own small PDF writer (no library),
             Telecomlijn details, company, line items, BTW, IBAN placeholder, "Download PDF"
             button on every invoice.
  Recurring  recurring_invoices (company, description, amount, BTW, every month / quarter /
             year, next date, active). recurring.php to add, pause and delete. Due ones are
             created automatically when the site is opened (at most once per run per
             schedule) and also with a "Run now" button; a real server would call it from a
             scheduled task. Created invoices use the normal numbering.
  Tests      PDF opens and contains the right totals, a schedule creates exactly one invoice
             per period, pausing works, no duplicates on repeated runs.
  Depends on Stage 1 (companies).

STAGE 11  Light mode toggle                                                  (suggestion 11)
-----------------------------------------------------------------------------------------------
Needs
  Theme      colours move from fixed hex values to CSS variables, a light palette is added,
             a sun / moon button in the top bar, the choice is remembered per browser and
             follows the system setting by default. The dark design stays the default look.
  Care       every page (including Uptime, login, privacy pages) is checked in both modes,
             contrast must pass WCAG AA in both, charts and badges keep readable colours.
  Tests      axe contrast scan of all pages in light mode, screenshots of main pages.
  Best done after the new pages exist, so they are covered too.

STAGE 12  Phone layout for tables                                            (suggestion 12)
-----------------------------------------------------------------------------------------------
Needs
  Layout     below 640 px every table turns into stacked cards with the column name beside
             each value (labels are filled in automatically from the table headers), sort
             and filter controls stay reachable, no sideways scrolling.
  Care       accessibility roles are kept so screen readers still read it as a table.
  Tests      360 px screenshots of every table page, axe scan, no horizontal overflow.
  Best done last, so all new tables from earlier stages are included.


AFTER THE LAST STAGE
  - Update README.md and the Settings > Tests log, regenerate the database dumps in
    database/, run the full test suite and the whole-site crawl once more.
  - Commit locally; push to GitHub only when you say so.

SUGGESTED ORDER (follows the dependencies above)
  1 Companies -> 2 Notes -> 3 Tickets -> 4 Search -> 5 Export/Import -> 6 Notifications
  -> 7 Two-factor -> 8 Email/reset/invites -> 9 Trends -> 10 PDF + recurring
  -> 11 Light mode -> 12 Phone tables
  Stages 7 and 8 can swap places; 11 and 12 should stay last.
